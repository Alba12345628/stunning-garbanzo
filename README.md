# MMR Tracker

Рейтинговый трекер практики в стиле доты: минуты → MMR → ранг со звёздами.
Чистая статика, без сборки и без бэкенда. Прогресс лежит в `localStorage`
браузера — на каждом устройстве свой.

```
index.html    разметка
styles.css    тёмная тема
app.js        вся логика: MMR, звёзды, серии, пропуски, теплокарта
```

## Правила

| Правило | Значение |
|---|---|
| Базовый фарм | 1 мин = **+2,5 MMR** |
| Серия 3+ дня | множитель **x1.5** |
| Серия 7+ дней | множитель **x2.0** |
| Кап анти-тильта | **20 мин/день**, минуты сверх не дают MMR |
| Пропущенный день | **−100 MMR**, серия обнуляется |

Множитель считается по серии **включая сегодняшний день**: третий день подряд
уже фармится с x1.5. MMR не уходит в минус — нижняя граница 0.

## Ранги и звёзды

Каждый ранг делится на 5 звёзд, у ТИТАНа звёзд нет.

| Ранг | MMR | Шаг звезды |
|---|---|---|
| Рекрут · Herald | 0 – 750 | 150 |
| Страж · Guardian | 751 – 1500 | 150 |
| Рыцарь · Crusader | 1501 – 2300 | 160 |
| Герой · Archon | 2301 – 3100 | 160 |
| Легенда · Legend | 3101 – 3900 | 160 |
| Властелин · Ancient | 3901 – 4700 | 160 |
| Дивайн · Divine | 4701 – 5400 | 140 |
| ТИТАН · Immortal | 5401+ | — |

Считает хелпер `getRankAndStars(mmr)` в [`app.js`](app.js). Он возвращает ранг,
номер звезды, готовый тайтл (`Герой 3`), сколько MMR до следующей звезды и
процент заполнения текущей.

Отсчёт внутри ранга идёт от значения **перед** его началом, поэтому границы
совпадают с таблицей: Страж 1 = 751–900, Рыцарь 1 = 1501–1660,
Дивайн 1 = 4701–4840. Рекрут начинается с нуля, и его первая звезда на единицу
шире (0–150).

> В исходной спеке Страж начинался с 760, из-за чего диапазон **751–759**
> не принадлежал ни одному рангу. Здесь Страж начинается с 751.

## Наиграно часов

Плашка рядом с MMR суммирует **все** минуты из истории — включая те, что
срезал дневной кап. Это счётчик вложенного времени, а не очков, поэтому
20-минутный лимит на него не влияет. Формат `X.X hrs`.

## График активности

Теплокарта в стиле GitHub: 7 строк — дни недели (пн сверху), колонки — недели.
Переключатель периода: `All` (вся история, минимум 12 недель), `30d`, `7d`.
Выбор запоминается. Заливка по сумме минут за день:

| Минут | Цвет |
|---|---|
| 0 | нейтральный фон |
| 1–10 | тёмно-синий |
| 11–20 | средний |
| 21–30 | яркий |
| 31–40+ | максимально яркий |

Принятые пропуски — красная клетка с `✕`, найденные но не принятые — красный
пунктир. В тултипе дата, суммарное время и разбивка по каждому навыку.

## Навыки

Из коробки — губная гармошка и горловое пение. Свои добавляются прямо в
интерфейсе: значок (любой эмодзи) + название, до 10 активных одновременно.

Убранный навык не удаляет историю: его минуты остаются в «наиграно», в журнале
и на теплокарте. Если добавить навык с тем же названием обратно — он вернётся
со всей накопленной статистикой.

## Пропуски

Работают два механизма, и они не штрафуют дважды.

**Автоматически.** Приложение сверяет календарь: если между последним
засчитанным днём и вчера есть дыры, наверху появляется красный блок Abandon и
**фарм блокируется**, пока поражение не принято. Сегодняшний день пропуском не
считается, пока не закончился.

**Вручную.** Кнопка «Пропустил день» под формой. Если приложение уже нашло
дыру — кнопка закрывает самую старую из них. Если дыр нет — оформляет
добровольный абандон на сегодня. В обоих случаях −100 MMR и серия в ноль.

## Настройка

Всё, что стоит трогать, лежит в начале [`app.js`](app.js):

```js
const MMR_PER_MINUTE  = 2.5;
const DAILY_CAP       = 20;
const ABANDON_PENALTY = 100;
const CAP_MODE        = 'total';   // или 'per_skill'
const STREAK_TIERS    = [ { days: 7, mult: 2.0 }, { days: 3, mult: 1.5 } ];
const HEAT_LEVELS     = [ /* пороги заливки теплокарты */ ];
```

`CAP_MODE` решает, как делится дневной лимит:

- `'total'` — 20 минут в день **на все дисциплины вместе** (так написано в спеке).
  Минус: 20 минут гармошки обнуляют MMR за остальные навыки в этот день.
- `'per_skill'` — по 20 минут **на каждую дисциплину**.

## Локальный запуск

Достаточно открыть `index.html` двойным кликом. Если браузер ограничивает
`localStorage` на `file://`, подними любой статический сервер:

```bash
npx serve .
```

## Деплой на Vercel

Проект — голая статика, никаких настроек не нужно. Сначала один раз
авторизоваться:

```bash
npx vercel login
```

Потом из этой папки:

```bash
npx vercel --prod
```

На вопросы про build command и output directory жми Enter — статика
раздаётся из корня как есть.

Через веб-интерфейс: залей папку в репозиторий на GitHub, в Vercel нажми
**Add New → Project**, выбери репозиторий. Framework Preset определится как
**Other**, Build Command и Output Directory оставь пустыми.
